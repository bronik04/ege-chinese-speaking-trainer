# Поддержка Range для аудио из S3/R2

## Цель

Сделать приватные записи ответов одинаково перематываемыми при локальном и S3/R2-хранилище, не выдавая клиенту публичные URL объектов.

## Область изменений

Изменение касается только `GET /api/recordings/{recording_id}`. Доступ к записи по-прежнему проверяется до чтения объекта. Статические файлы и изображения материалов в эту работу не входят.

## HTTP-контракт

Маршрут принимает один диапазон байтов в заголовке `Range`.

- Без `Range` возвращается текущий потоковый ответ `200`.
- Корректный единичный диапазон (`bytes=start-end`, `bytes=start-` или `bytes=-length`) возвращает `206`.
- Ответ `206` содержит `Accept-Ranges: bytes`, точный `Content-Range` и `Content-Length` выбранного фрагмента.
- Невалидный, выходящий за размер файла или множественный диапазон возвращает `416` и `Content-Range: bytes */<полный размер>`.
- Суффиксный диапазон длиннее записи нормализуется до всей записи.

Размер записи уже хранится в `FileResult.size_bytes`; для разбора диапазона дополнительный запрос к S3 не нужен.

## Реализация

В API-модуле появится чистый разбор единственного HTTP Range в границы `start` и `end`. Он не зависит от FastAPI и тестируется отдельно.

`file_response` получит исходный `Request` и будет действовать так:

1. Для локального backend сохранит `FileResponse`: Starlette сам эффективно обрабатывает Range для файла.
2. Для удалённого backend использует распарсенный диапазон и передаст его storage-adapter.
3. Для `206` выставит точные HTTP-заголовки и поток только выбранных байтов.

Контракт `AudioStorage` расширится операцией потокового чтения диапазона. Локальный adapter читает только указанную часть файла; S3/R2 adapter вызывает `get_object` с параметром `Range=bytes=start-end`. Обычная потоковая выдача остаётся совместимой и использует полный объект.

## Ошибки и устойчивость

Ошибки отсутствующего объекта сохраняют текущую семантику `FileNotFoundError` и преобразуются существующим API-слоем. Неподдерживаемый multipart Range не пытается собираться в multipart/byteranges-ответ: сервер отвечает `416` без чтения объекта.

## Проверка

- Unit-тесты разбора Range: обычный, открытый, суффиксный, невалидный и множественный варианты.
- Integration-тест записи через API проверяет `206`, заголовки и тело для локального backend, а также `416`.
- Тест S3 adapter проверяет вызов `get_object` с корректным параметром `Range` и отдачу только полученных байтов.
- Обязательный `make check`; UI не меняется, поэтому E2E не требуется.

## Не входит в задачу

- Presigned URL и прямой доступ браузера к S3/R2.
- Диапазоны для изображений и других материалов.
- Multipart Range.
