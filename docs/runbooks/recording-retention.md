# Хранение и удаление аудиозаписей

## Назначение

Ответы зарегистрированных учеников и копии аудио в заявках на разбор хранятся ровно шесть календарных месяцев в UTC. По истечении срока метаданные удаляются из базы, поэтому запись сразу перестаёт открываться через API. Затем ключ файла попадает в устойчивую очередь очистки и удаляется из закрытого storage; временная ошибка storage не возвращает доступ к записи и будет повторена следующим запуском.

Гостевые записи на сервер не отправляются и эта процедура к ним не относится.

## Ежедневный запуск

Запускайте один раз в сутки от имени пользователя, у которого доступны те же переменные окружения, база и закрытое аудиохранилище, что и у приложения:

```bash
.venv/bin/python -m scripts.cleanup_storage
```

В Docker:

```bash
docker compose exec app python -m scripts.cleanup_storage
```

Пример cron-задачи на 03:20 UTC:

```cron
20 3 * * * cd /srv/chinese-speaking-trainer && /srv/chinese-speaking-trainer/.venv/bin/python -m scripts.cleanup_storage >> /var/log/chinese-trainer/recording-retention.log 2>&1
```

Команда выводит `expired`, `completed`, `failed` и `pending`. Ненулевой код возврата означает, что хотя бы одна задача физической очистки не завершилась и требует повторного запуска или проверки storage. Повторный запуск безопасен: уже удалённые метаданные не выбираются повторно, а ожидающие ключи обрабатываются очередью.

При каждом запуске приложения такая же очистка выполняется best-effort до обычной обработки очереди. Она не заменяет ежедневную задачу: при недоступном storage старт приложения намеренно не блокируется.

## Проверка и действия при ошибке

1. Проверьте структурированные логи приложения и вывод команды: количество `failed`/`pending` должно стать нулём после успешного повторного запуска.
2. Убедитесь, что у S3/R2 credentials есть права удаления только в настроенном закрытом bucket; для локального режима проверьте права на `TRAINER_DATA_DIR`.
3. Не восстанавливайте строки `personal_recordings` или `review_request_recordings` вручную: после истечения срока доступ не должен возвращаться.
4. Если очередь остаётся pending после восстановления storage, повторите команду. Для расследования сохраните request ID и логи, затем следуйте [процедуре инцидента](incident-response.md).

Удаление аккаунта также добавляет личные аудиозаписи в эту же устойчивую очередь; ручное удаление файлов в обход очереди не требуется.
