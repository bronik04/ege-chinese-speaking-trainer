# Гайдлайн для AI-агентов: модели, effort, плагины

Документ адресован AI-агентам (Claude Code), работающим в этом репозитории. Он не переопределяет обязательные
правила [AGENTS.md](../AGENTS.md) и [SECURITY.md](../SECURITY.md) — это рекомендация по инструментам, а не gate
вроде `make check`.

## Модель и effort по типу задачи

Глобальный дефолт окружения — `model: opus`, `effortLevel: xhigh`. Это безопасный выбор для security-чувствительных
и архитектурных задач, но избыточен для рутины. Ниже — когда стоит явно понижать модель/effort через `/model` и
`/config`, а когда оставаться на дефолте или наоборот повышать effort.

| Тип задачи | Модель | Effort | Почему |
|---|---|---|---|
| Механическая правка: переименование, опечатка, форматирование, правка одной строки в JSON/JS/Python | Haiku 4.5 | low | не требует глубокого рассуждения, важна скорость |
| Обычная фича/фикс в существующем слое: `api/routes`, `api/controllers`, `services/`, JS-модуль, тест | Sonnet 5 | medium | основной поток задач проекта |
| `domain/`-правила, изменение границ слоёв, Alembic-миграция (dual-dialect SQL) | Sonnet 5 | high | нужно удерживать инварианты: frozen SQLite baseline, `API → domain → infrastructure` |
| Security-sensitive зоны из [SECURITY.md](../SECURITY.md): accounts, storage, mailer, transcription, auth, deploy-конфигурация | Opus 5 | high/xhigh | документ явно требует расширенной проверки |
| Ревью перед мержем, `/code-review`, security-review | Opus 5 | xhigh | нужна независимая, придирчивая проверка |
| Отладка непрозрачного бага (`systematic-debugging`) | Opus 5 | high | нужны множественные гипотезы, а не первая правдоподобная |
| Контент/задания ЕГЭ через скилл `ege-chinese` | Sonnet 5; Opus 5 для спорных формулировок | high | точное соответствие спецификации ФИПИ важнее творческой свободы |
| Документация (README, ADR, CLAUDE.md, этот файл) | Sonnet 5 | medium | |

Правило по умолчанию: если задача явно не подходит ни под одну строку — оставайтесь на дефолте (`opus`/`xhigh`),
не подбирайте модель под настроение.

## Плагины и скиллы, относящиеся к проекту

### Локальные плагины (`claude-plugins-official`, видны в `~/.claude/plugins/installed_plugins.json`)

| Плагин | Статус в проекте | Почему |
|---|---|---|
| `superpowers` | используется | brainstorming, TDD, systematic-debugging, code review — общий инженерный процесс, применим к любому языку |
| `frontend-design` | используется | в проекте есть `frontend/` (vanilla JS, без сборки) |
| `typescript-lsp` | отключён для этого проекта | в репозитории нет TypeScript |
| `swift-lsp` | отключён для этого проекта | в репозитории нет Swift |
| `preset-cli-skills` | уже отключён (глобально) | — |

Отключение `typescript-lsp` и `swift-lsp` сделано в закоммиченном `.claude/settings.json` этого репозитория, а не
глобально в `~/.claude/settings.json` — чтобы не задеть другие проекты пользователя, где эти языки используются.

### Встроенный набор скиллов текущего окружения (Cowork)

`anthropic-skills:*`, `design:*`, `operations:*`, `productivity:*`, `dataviz`, `cowork-plugin-management` и
похожие — не локальные плагины и не управляются файлами этого репозитория; переключаются только в настройках
самого Cowork/claude.ai.

Из этого набора для проекта уместны:

- `ege-chinese` (`anthropic-skills:ege-chinese` и одноимённый top-level) — генерация и разбор заданий ЕГЭ по
  китайскому, ядро контентной части тренажёра;
- `dataviz` — разовые графики/дашборды (например, прогресс ученика), если понадобится визуализация вне UI
  тренажёра;
- `design:accessibility-review`, `design:design-critique` — точечно, при работе над `frontend/`.

Остальные группы (`operations:*`, `productivity:*`, большая часть `design:*`, `cowork-plugin-management`) к
задачам этого репозитория не относятся: это CRM/процессный тулинг, а не веб-приложение на FastAPI. Отключать их
для конкретного проекта штатных средств Claude Code нет — это глобальная настройка окружения; при желании
пользователь может убрать лишнее в настройках Cowork самостоятельно.
