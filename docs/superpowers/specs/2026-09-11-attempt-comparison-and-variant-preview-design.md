# Сравнение попыток и безопасный предпросмотр вариантов

Дата: 2026-09-11

## Контекст

Страница истории уже объединяет попытки, личные аудиозаписи и заявки на разбор по `runId`, но пользователь
может рассматривать их только по одной. Каталог вариантов, напротив, загружает полное содержимое каждого
доступного материала, однако карточка показывает только одно изображение и сразу ведёт на главный экран
тренажёра. Пользователь не видит, какие изображения входят в задания 2 и 3, пока не начнёт тренировку.

Нужно добавить два последовательных пользовательских сценария:

1. сравнение двух завершённых сопоставимых попыток по заданиям, оценкам и записям;
2. отдельный визуальный предпросмотр варианта без раскрытия вопросов и подсказок.

## Цели

- Дать авторизованному ученику выбрать в истории две завершённые попытки с одинаковым набором заданий.
- Сопоставить по каждому заданию оценки, изменение балла и аудиозаписи в одинаковом порядке.
- Сохранить полезную часть сравнения при отсутствии оценки, записи или временной ошибке одного источника.
- Открывать из каталога отдельную страницу варианта со всеми относящимися к нему изображениями.
- Не помещать в DOM предпросмотра ситуацию, вопросы, баннер, план ответа, стартовую фразу и другие
  содержательные подсказки.
- Сохранить текущую дизайн-систему, мобильную вёрстку, клавиатурную навигацию и границы ответственности.

## Не входит в работу

- Аналитические графики, серии занятий и автоматические рекомендации следующей тренировки.
- Сравнение прерванных попыток или попыток с разным набором заданий.
- Сравнение более двух попыток одновременно.
- Новая система оценивания, автоматическая проверка речи или транскрибация.
- Изменение схемы прогресса, базы данных либо существующих HTTP-контрактов.
- Криптографическое сокрытие содержания материала. Действующий detail API уже отдаёт доступный материал
  браузеру; предпросмотр отвечает только за то, какие поля оказываются на странице и в accessibility tree.

## Общий порядок

Функции реализуются двумя отдельными вертикальными срезами. Сначала завершается и проверяется сравнение
попыток, затем — предпросмотр каталога. Они используют общую навигацию сайта, но не зависят друг от друга и
не требуют общего нового сервиса.

## Сравнение попыток

### Доступ и выбор

Полноценное сравнение доступно только авторизованному пользователю с ролью `student`. У гостя нет
долговечных аудиозаписей и оценок, поэтому история сохраняет существующее приглашение войти и не предлагает
малоинформативное сравнение. Для преподавателя остаётся отдельный сценарий истории проверок.

В каждой карточке завершённой попытки ученика появляется доступный с клавиатуры элемент выбора. Прерванные и
восстановленные только из архивного источника записи не участвуют в выборе. После выбора первой попытки:

- совместимы только завершённые попытки с тем же отсортированным набором заданий;
- несовместимые элементы остаются видимыми, но становятся недоступны для выбора и объясняют причину;
- можно выбрать ровно одну вторую попытку;
- панель действия показывает число выбранных попыток и активирует кнопку «Сравнить» только при двух.

Сравнивать можно одинаковый режим заданий из разных вариантов: полный экзамен с полным экзаменом или,
например, тренировку задания 2 с другой тренировкой задания 2. Название варианта всегда видно, чтобы
различие материалов не потерялось.

Кнопка открывает `compare.html?left=<run-id>&right=<run-id>`. Идентификаторы не считаются секретами, но при
чтении ограничиваются уже действующим контрактом прогресса, декодируются как строки и используются только
для поиска внутри данных текущего авторизованного ученика. При перезагрузке страницы выбор восстанавливается
из URL; при отсутствии одной из попыток показывается понятная ошибка без подстановки другой записи.

### Источники и модель данных

Новый серверный endpoint не нужен. Страница сравнения переиспользует действующую загрузку истории:

- прогресс пользователя;
- `/api/personal-recordings`;
- `/api/review-requests`.

Данные объединяются существующей моделью истории по `runId`. Поверх неё создаётся чистая модель сравнения,
которая:

- проверяет роль, завершённый статус и равенство набора заданий;
- сортирует две попытки по выбранным сторонам, а не по дате;
- для каждого задания выбирает последний запрос со статусом `reviewed`, содержащий это задание; порядок
  определяется по `reviewedAt`, затем `submittedAt` и `id`;
- берёт общий балл задания, максимум и разбивку `scores` из соответствующего item;
- вычисляет числовую разницу только когда обе стороны имеют оценки с одинаковым максимумом;
- выравнивает личные записи по паре `(taskNumber, questionNumber)`; у review-записи номер задания берётся из
  родительского item, а позиция — из `question_number`/`questionNumber`;
- использует запись из review request только как запасной источник, если личной записи для позиции нет;
- не дублирует один и тот же ответ одновременно в личном и review-блоке.

Для задания 1 ожидаются позиции вопросов 1–5, для заданий 2 и 3 — одна позиция ответа. Отсутствие позиции не
сдвигает соседние записи: на соответствующей стороне остаётся явное состояние «Запись недоступна».

### Страница сравнения

Страница сохраняет общую шапку и ссылку назад в историю. Вверху находятся две компактные карточки попыток с
датой, вариантом, режимом и итоговой доступностью данных. Ниже располагаются секции по заданиям. Каждая
секция содержит две согласованные колонки:

- общий балл задания и максимум;
- значения критериев с человекочитаемыми названиями;
- индикатор изменения второй попытки относительно первой;
- пары аудиоплееров в одинаковых позициях.

Рост балла обозначается спокойным положительным состоянием, снижение — предупреждающим, равенство —
нейтральным. Цвет никогда не является единственным носителем смысла: рядом выводятся знак и числовое
значение. Если завершённого разбора нет, отображается «Оценки пока нет». Истёкшая или отсутствующая запись
отображается как «Запись недоступна».

### Ошибки

Контроллер сохраняет независимые состояния загрузки `progress`, `recordings` и `reviews`, как текущая
история. Ошибка одного источника не стирает успешно загруженные данные. Для каждого проблемного источника
есть отдельная кнопка повтора. Ошибка авторизации возвращает страницу в состояние входа и не показывает
ранее загруженные данные другого аккаунта. Ответы, пришедшие после смены пользователя, игнорируются по
generation token.

## Предпросмотр варианта

### Навигация каталога

Основное действие карточки в `variants.html` меняется с немедленного перехода к тренажёру на открытие
`variant-preview.html?variant=<material-id>`. Текст действия становится «Предпросмотр». Вся понятная область
карточки использует stretched-link, но сохраняется один семантический `<a>`, чтобы не создавать
вложенные интерактивные элементы.

На странице предпросмотра есть:

- ссылка «Назад к вариантам»;
- название, источник, год, тип материала и примерная продолжительность;
- секции входящих заданий;
- явная кнопка «Перейти к тренировке», ведущая на `index.html?variant=<material-id>`.

Для полного варианта показаны задания 1–3. Для материала `kind: "task"` показано только его задание.

### Безопасная проекция

Страница получает материал из существующего `/api/materials/{id}`, затем передаёт его в чистую функцию
проекции. В результирующую view model входят только:

- `id`, `label`, `source`, `year`, `kind`, `taskNumber`, `totalMinutes`;
- номер и нейтральное название задания;
- `image` задания 1 либо массив `images` заданий 2 и 3;
- `imageAlt` и `imageLabels`, если они заданы.

Не копируются и не рендерятся `situation`, `banner`, `questions`, `lead`, `prompts`, `starter` и любые
неизвестные поля. Тесты проверяют не только отсутствие видимого текста, но и отсутствие скрытых значений в
HTML и accessibility tree.

Изображения группируются так:

- задание 1 — одно изображение;
- задание 2 — три изображения;
- задание 3 — два изображения.

Подписи берутся из `imageLabels`; при их отсутствии используется безопасный нейтральный alt вида
«Изображение 2 задания 3». Разрешены только относительные same-origin пути `assets/`, `/assets/` и
`/api/material-assets/`; пустой или иной URL не создаёт `<img>`, а показывает состояние недоступного
изображения. Доступ к официальным и пользовательским материалам остаётся под действующими
правилами detail API. `404`, `403` и сетевые ошибки дают страницу ошибки с возвратом в каталог и повтором
загрузки, не сохраняя чужой ответ в UI.

### Компоновка

Утверждена отдельная страница (макет A), а не раскрытие карточки и не боковая панель. На широком экране
метаданные и основное действие находятся в верхней области, ниже идут три последовательные секции. Галерея
задания 2 имеет три колонки, задания 3 — две. На узком экране изображения переходят в одну колонку без
горизонтальной прокрутки; основные действия имеют высоту не менее 44 px.

После загрузки фокус перемещается на заголовок страницы. При ошибке фокус получает заголовок ошибки.
Порядок клавиатурной навигации: возврат в каталог, содержимое страницы, переход к тренировке.

## Компоненты

Изменения следуют текущим границам frontend:

- `frontend/js/history/` — совместимость выбора и чистая модель сравнения;
- `frontend/js/history/history-page.js` и view — выбор двух завершённых попыток;
- новый контроллер и view страницы `compare.html`, переиспользующие текущую загрузку истории;
- `frontend/js/catalog/variant-catalog.js` — ссылка на предпросмотр;
- новая чистая модель проекции и контроллер страницы `variant-preview.html`;
- новые HTML-страницы и профильные CSS-файлы;
- существующие API, domain, services, infrastructure и схема БД не меняются.

Если переиспользование `createHistoryPageController` требует небольшой экстракции общего loader, она должна
сохранить его текущий публичный контракт и отмену устаревших запросов. Параллельный history service создавать
не следует.

## Проверка

### JavaScript unit tests

- завершённые попытки с одинаковыми заданиями совместимы независимо от варианта;
- прерванные, восстановленные и несовместимые попытки не выбираются;
- разрешено ровно две попытки;
- выбирается последний завершённый разбор для каждого задания;
- score delta вычисляется только для сопоставимых оценок;
- записи выравниваются по заданию и позиции, personal имеет приоритет над review;
- частично отсутствующие данные порождают явные пустые состояния;
- безопасная проекция предпросмотра содержит изображения и исключает все содержательные поля;
- HTML экранирует сетевые строки и отбрасывает небезопасные URL.

### Playwright

- авторизованный ученик выбирает две совместимые попытки и открывает сравнение;
- несовместимая и прерванная попытка остаётся видимой, но недоступной;
- сравнение показывает оценки, разницу и попарные аудиоплееры;
- отсутствие оценки или записи не ломает страницу;
- частичная ошибка источника сохраняет остальные данные и повторяется отдельно;
- гость и преподаватель не получают ученическое сравнение;
- каталог открывает отдельный предпросмотр;
- полный официальный вариант показывает 1 + 3 + 2 изображения;
- содержательные вопросы и подсказки отсутствуют в DOM;
- CTA открывает главный экран с тем же `variant`;
- task-only материал показывает одну соответствующую секцию;
- обе новые страницы помещаются в ширину 360 px, имеют touch targets не менее 44 px и работают с клавиатуры.

После реализации обязательны свежие успешные `make check` и `make test-e2e`.

## Документация

README описывает выбор двух попыток, ограничения доступа, значения пустых состояний и предпросмотр изображений
без вопросов. Архитектурная документация меняется только если при реализации понадобится новая общая граница,
чего текущий дизайн не предполагает.
